版本：方案 v1.1 · 2026-10-29  
本轮交付：完整产品与实施方案。下文未标记为“当前已有”的内容均为待实现要求，不能作为已经完成或已经发布的功能说明。

## 1. 产品定位与目标

Work 服务于个人科研工作的完整过程：整理研究问题、安排时间、收集资料、阅读和分析、与 AI 协作、记录实验、形成成果、复盘进度。Agent、日历和专注工具共享任务与项目上下文。

日常首页应回答四件事：今天要做什么、下一件最重要的事是什么、现在专注于什么、最近产生了哪些成果。

范围澄清：本方案中的番茄钟、喝水、休息与活动提醒主要服务于文献阅读，主入口和使用流程在 Paper 阅读器；Work 承接阅读安排与记录汇总。

首个完整版本面向个人、本地科研工作区。多人协作、跨设备同步和完整实验计算平台列为后续扩展，不作为这一版完成的前提。

### 3.1 一级入口

| 入口 | 核心内容 |
|---|---|
| 今日 | 今日任务、临近截止、日程、专注状态、近期成果、待处理事项 |
| 科研项目 | 研究目标、任务、里程碑、材料、日志、成果 |
| 科研日历 | 月/周/日/议程、时间安排、截止日期、重复日程 |
| AI 任务 | 会话、计划、执行过程、审批、队列、产物 |
| 研究记录 | 阅读笔记、研究日志、实验记录、会议记录 |
| 成果 | 综述、对比表、报告、引用清单、导出文件 |
| 技能与连接 | 技能管理、MCP 与现有平台能力 |

文献阅读番茄钟和阅读提醒从 PDF 阅读工具栏及侧栏访问；Work 展示当前阅读状态并可跳回论文。Paper 模式承接文献库、PDF 阅读及读文献时的专注支持。

### 3.2 布局原则

- 左栏负责导航、项目与会话；中央负责当前工作；右侧按需展示材料、任务详情、计划或产物。
- 分栏支持拖拽、折叠、键盘调整、复位，并记忆宽度；窄窗采用单主视图加抽屉。
- 对话输入区统一提供“添加材料、引用上下文、选择技能、模型/思考强度、执行方式、发送/停止”。
- 主要操作常驻；次要操作进入有明确名称的菜单。复制回答、导出报告、恢复运行等文字分别说明作用对象。
- 任务中仅保留一层输入容器；减少无意义卡片嵌套和重复边框。
- 阅读计时条以 PDF 阅读器为主；Work 只展示同一阅读会话的状态与返回入口，不遮挡文档正文。
- 品牌资产统一，深浅主题、字号缩放、键盘焦点、屏幕阅读器和减少动画均纳入验收。

## 4. 今日工作台

- 显示今天的安排、逾期任务、临近截止、当前专注、待审批 Agent 任务与最近成果。
- 支持快速添加研究任务、日程、便签，继续上次阅读或未完成会话。
- 允许调整首页模块顺序、折叠和隐藏；空模块提供对应操作，避免展示假数据。
- “下一步”优先来自用户设置的优先级与时间；AI 建议明确标为建议，并说明依据。
- 首页的任务数量、进度、专注分钟均从真实记录计算，切换项目后范围明确。

## 5. 科研项目、任务和里程碑

- 项目包含名称、研究问题、目标、状态、起止日期、标签和关联材料。
- 任务支持待办、进行中、等待条件、已完成、已取消；可设置优先级、预计耗时、截止日期和子任务。
- 提供列表与轻量看板；支持搜索、筛选、排序和批量归档。
- 项目任务可关联论文、文件、笔记、实验、会话、日程、专注记录和产物。
- 一条科研任务可以有多次 AI 运行；单次 AI 回答结束不自动宣告科研任务完成。
- 里程碑描述可核实的交付物，例如“完成 10 篇精读并形成方法对比表”，保留依据和确认记录。
- 科研任务完成以用户确认或已定义的验收结果为准；撤销完成后保留历史。

## 6. 科研日历与时间安排

- 提供月、周、日和议程视图，以及今天、上一段、下一段、直接选日期。
- 日程类型包括研究任务、阅读、实验、会议、截止日期、里程碑；支持全天或具体时间、持续时长和时区。
- 任务可安排时间块；日历拖动只改安排时间，不悄悄改变截止日期。
- 支持重复日程、例外日期、修改本次/以后/整组，过期和冲突有清楚提示。
- 可关联项目、文献、任务和会话；从日程打开材料、开始专注、进入关联会话或准备 AI 任务草稿。
- 创建 AI 草稿不等于启动执行；明确显示下一步动作。
- 会议/投稿截止可填写来源链接与时区；自动解析得到的日期先作为待确认信息。
- 支持手动日程和 ICS 导入/导出；后续阶段再增加外部日历账户同步。
- 全天日期使用日历日期，定时事件保存时间和时区；跨时区、夏令时、月末和闰年独立测试。
- 日历只安排时间；需要自动执行的任务必须在自动化中明确启用。

## 7. 文献阅读番茄钟与阅读专注

### 7.1 使用位置与关联对象

- 主入口放在 Paper 的 PDF 阅读工具栏及阅读侧栏，在当前论文里即可开启、暂停、查看和结束。
- Work 的今日首页、科研日历和阅读任务用于安排阅读、打开论文及查看记录，不要求用户离开 PDF 才能操作计时。
- 番茄钟绑定当前论文或阅读清单，可同时归属某个科研项目/阅读任务；不默认把一般 Agent 工作当成阅读。
- 适用于阅读正文、批注、查看该论文的引用和相关笔记；界面保持文献为主，计时条不遮住正文或选区操作。
- 本版先交付文献阅读场景。通用办公、实验、编程等专注模式属于后续扩展，不纳入本次番茄钟验收。

### 7.2 核心功能

- 支持阅读专注、短休息、长休息及阅读自由计时，预设可编辑。
- 初始产品预设可为 25 分钟阅读、5 分钟短休、15 分钟长休，每 4 段进入长休；用户可按阅读习惯调整。
- 支持开始、暂停、继续、提前结束、跳过休息和重置；提前结束单独记录，不计作完整番茄。
- 在多篇论文间切换时，同一段阅读专注可以继续，分段记录每篇的阅读时间，避免重复启动计时。
- 结束一段后，可补充阅读收获、标记阅读进度、稍后继续或进入下一段；完成番茄不自动把论文标为已读。
- 休息结束提示“继续阅读”，默认由用户启动下一段；自动衔接由用户单独启用。
- 同一应用只允许一个活动阅读计时，多窗口同步；阅读清单和当前论文归属始终可见。

### 7.3 阅读边界与恢复规则

- 主进程持有状态，切换论文、重载阅读界面不会重置计时。
- 阅读页离开前台、关闭文献、切入无关 Work/其他应用或最小化时，暂停阅读时间累计；返回文献后显示继续入口。
- 短/长休息倒计时可以在后台继续；休息结束只提醒一次，不自动累计下一段阅读。
- 锁屏、系统睡眠暂停阅读与相关提醒；唤醒后恢复入口保留，离线时间不计入阅读专注。
- 应用退出时保存为暂停状态；重启后由用户继续，不补算整段离线时间。
- 采用持久起止时刻、暂停区间与单调时钟校准，不依靠页面 setInterval 递减；系统改时不生成负数或异常超长记录。
- 阅读页前台时长、用户启动的番茄记录、AI 执行时间分别统计，不把页面打开或 Agent 等待等同于有效阅读。
- 与现有论文 read_seconds / read_log 统计协调，避免新旧计时器同时累加造成双倍时长。
- 不能只根据鼠标、键盘是否活动断定用户没在读论文；保留手动暂停阅读入口。

## 8. 读文献时的喝水、休息与活动提醒

### 8.1 提醒触发范围

- 提醒针对连续文献阅读：喝水、起身活动、短暂休息和视线放松，用户分别启用和配置间隔。
- 在阅读器内打开设置；不启动番茄钟也可以启用阅读提醒，以阅读页前台累计时长为依据。
- 提醒时间随阅读会话累计，离开阅读场景时暂停；关闭文献或整天未读论文时，不持续发送阅读提醒。
- 规则可以全局保存，但触发条件绑定阅读状态；不因为应用运行或 Agent 正在执行就触发喝水/休息提示。
- 支持“已处理、稍后提醒、跳过这次、本次阅读不再提醒、关闭此类提醒”。
- “暂停番茄”与“暂停阅读提醒”分别说明作用；前者不自动关闭仍在阅读时的独立提醒。
- 记录提醒处理与主动登记行为，不推断实际饮水量。

### 8.2 与阅读节奏的配合

- 番茄短休开始时合并喝水、起身和视线放松提示，避免同一分钟多个弹窗。
- 阅读或批注中默认使用不抢焦点的轻提示，可选择延后到当前阅读段结束。
- 用户选择稍后后，按其选择与恢复阅读状态安排下一次，不重复弹同一条旧提醒。
- 提供阅读免打扰、安静时段和可关闭的声音；提示不打断输入法、批注编辑或选区。
- 应用内提示与系统通知共享处理状态，多窗口也只能处理同一提醒一次。
- 最小化期间暂停阅读累计，保留休息倒计时和待恢复状态；睡眠、锁屏、应用退出期间的旧提示不批量补发。
- 休息不会暂停后台 Agent；科研日程截止和 AI 审批继续按各自的通知规则处理。

### 8.3 Work 与 Paper 的分工

- Paper：实际读文献、启动阅读番茄、接收阅读提醒、记录本篇进度与阅读收获。
- Work：规划阅读清单与时间、从日历进入论文、查看按论文/项目汇总的阅读与专注记录。
- 两处使用同一套阅读状态和数据，不各自启动一套计时或提醒引擎。

## 9. 文件、附件与材料库

### 9.1 用户入口与支持范围

- 输入区提供文件选择、拖拽、移除和预览；粘贴图片在模型支持视觉时接入。
- “作为本次任务附件”与“导入文献库”各有明确入口，临时材料不会无提示地入库。
- 首批支持 PDF、TXT、Markdown、CSV、JSON；随后增加 DOCX、XLSX 和图片/OCR。
- 不支持的格式或模型能力明确说明，不能只显示文件名后宣称已经读过。
- 显示等待解析、解析中、可用、部分解析、失败和取消状态；支持重试与移除。
- 长文档、扫描 PDF、加密文件、表格和编码错误分别反馈；正文截断范围可见。

### 9.2 实际上下文链路

- 文件解析形成可定位的页、段落或表格范围，进入运行上下文并生成来源记录。
- 发送前可看见哪些材料参与本轮；回答点击引用能查看实际片段与对应位置。
- 原始文件版本、抽取版本和本次使用范围随运行保存；重试复用快照，重新读取则生成新版本。
- 切换项目和会话不串用材料；新任务的材料范围与旧会话独立。
- 文件解析及索引在后台工作线程执行，支持取消、超时和恢复，界面持续响应。
- 已发送材料的来源快照与草稿附件分开管理；清除草稿不会使历史引用失效。
- 存储位置、清理、导出和附件缺失恢复在设置中可见。

## 10. 上下文、阅读与文献平台联动

- 用统一材料面板管理当前论文、PDF 选区、文献集合、笔记、Web 内容、文件、项目和成果。
- 自动识别“这篇论文”时以当前阅读文献为依据，并在发送前显示引用对象。
- 题录与真实原文持续区分；无 PDF 不推断正文结论；解析失败提供修复入口。
- 输入 @ 可搜索文献、材料、任务和笔记；命令与引用候选可键盘操作。
- 显示本轮材料范围、检索状态和必要的上下文占用信息；超出预算时提供分批处理或检索方案。
- 阅读批注、对比表单元格、笔记段落可进入 Work；结果可回写到用户指定位置。
- 补齐 Work 对集合等已有上下文类型的 UI 接入，不能只在底层 schema 中“支持”。
- 继续覆盖用户早先 7 项问题：当前论文识别、Zotero 原文、右栏行为、模型思考档位、分栏、图谱缩放和详情抽取。

## 11. Agent 对话、模型与执行循环

- 模型按“服务商配置 + 模型”绑定；保留模型各自支持的思考等级、上下文能力和工具协议。
- 回复、思考摘要、工具步骤、审批和成果分层展示；不以普通占位文本代替执行状态。
- 运行过程采用“观察上下文 → 决定下一步 → 执行 → 读取结果 → 调整 → 验证完成”的循环。
- 工具返回的真实 ID、路径和结果供下一轮决策，不能提前编造后续工具参数。
- 优先使用模型原生工具调用；兼容模型可采用受验证的结构化协议，能力不足时清晰降级。
- 已移除面向用户的工具总步数控件；完成条件来自目标与证据。时长、成本和无进展保护作为独立机制，触发时说明具体原因并允许恢复。
- 重复无进展或异常循环需要停止并保留结果，不能静默耗尽资源。
- 区分“排队跟进”和“干预当前运行”；具备实现能力后再开放干预入口，并在安全的执行边界消费。
- 支持多轮澄清、编辑重发、重试、分支、归档、重命名与删除；运行中的会话操作与实际状态一致。
- 取消后保留已完成结果；对已经完成的外部动作明确记录实际状态，恢复时避免重复写入。

## 12. /plan 与 /goal 的完整语义

### 12.1 /plan

- 进入规划协作状态，可进行只读检索和材料分析；写入及外部变更由运行时禁止。
- 计划写清目标、材料范围、里程碑、交付物、待解决问题和验收条件；可审阅、编辑和继续讨论。
- 每次修订生成版本，保留修改差异与来源。
- “按此计划执行”绑定用户当前看到的计划版本及执行上下文，不能无提示地重新生成另一份计划替代。
- 执行中可基于观察调整步骤；发生目标或操作影响变化时生成可见修订，并按既定权限处理。
- 取消审阅与停止运行分别处理；编辑、重试、重启后保留规划模式。

### 12.2 /goal

- 目标归属于明确的项目或会话；旧版全局研究背景迁移为单独的背景设置。
- 目标包含客观交付物、完成条件、关联任务、状态、当前进展和证据。
- 支持草稿、进行中、暂停、等待条件、已完成、已取消，以及中断后的待恢复状态。
- 用户可暂停、恢复、修改或结束；模型不能擅自放宽目标、恢复用户已暂停的目标。
- 持续推进沿用同一目标和会话；用户消息与待审批操作优先于自主续跑。
- 完成前检查交付物和验证记录；只生成一段总结不算目标已达成。
- 阻塞必须给出具体条件、已有尝试和可继续入口；困难、超时或单次工具失败不等于任务完成。
- 应用重启后显示上次状态和恢复入口；自动恢复运行是否启用由用户明确设置。

### 12.3 命令与图形入口一致

| 命令 | 目标行为 |
|---|---|
| /plan | 查看/进入规划状态；带目标时对该目标开展只读规划 |
| /goal | 查看当前目标；带目标描述时进入创建流程 |
| /goal pause、resume、status、complete、cancel | 对当前目标执行明确的生命周期操作；完成仍检查验收依据 |
| /calendar | 打开科研日历并定位今天 |
| /focus | 打开当前论文的阅读专注面板；未打开论文时先选择阅读材料 |
| /remind | 打开阅读提醒设置，不凭无参数命令自动开启提醒 |
| /skills、/model、/deep | 使用与图形控件相同的技能、模型和思考强度配置 |

命令与按钮共用服务，不建立第二套状态。旧版“/goal 无参数清除全局目标”的行为改为查看目标，并在升级提示中解释；旧背景内容保留，清除必须是明确操作。

## 13. 技能与工具生态

- 技能支持搜索、分类、说明预览、选择、取消选择、启用/停用与用户目录刷新。
- 任务显示本轮技能；保存来源、版本和正文快照，重试与分支可追溯。
- 统一技能引用方式，可由输入区、技能页面或快捷命令选用。
- 对内置技能逐一校正过时工具名称、输入输出和完成条件。
- 工具可用性在执行前验证；技能缺依赖时说明缺少哪项能力。
- MCP 提供连接、测试、能力查看、错误恢复和配置入口；工具仍走统一权限、超时和操作记录。
- 技能步骤应结合执行结果驱动后续行为；仅把正文放进模型提示不作为技能完整落地的验收。
- 自动发现/建议技能后续提供，并显示选用理由，不能把所有技能全文无区别加入上下文。

## 14. 科研记录、成果与复盘

### 14.1 阅读与研究记录

- 阅读清单可关联项目任务、日历和专注记录；支持阅读状态、精读要点和追问。
- 研究日志记录问题、假设、证据、决定和下一步，可链接原论文与会话。
- 会议记录支持议题、记录和待办提取；提取的待办由用户确认后加入任务。
- 实验记录先提供轻量模板：目的、环境、数据版本、参数、指标、观察、附件与结论；后续再接计算平台。
- 明确区分原文结论、用户判断和 AI 推断。

### 14.2 成果管理

- 汇集综述、对比表、阅读笔记、研究报告、引用清单和导出文件，显示所属项目与来源。
- 支持预览、打开、搜索、版本、修改记录、导出和归档。
- “复制回答”“复制完整报告”“导出 Markdown/CSV”等操作清楚标注输出内容。
- AI 写入既有笔记、表格时保留版本和恢复入口；结果导航必须能打开实际产物。
- 周复盘从真实任务、记录、专注和成果计算；AI 可补充建议，但不编造进度与统计。
- 专注报表按任务/项目查看，并可导出或删除；不将 AI 等待时间当作用户劳动投入。

## 15. 自动化与通知中心

- 为定期文献检索、资料整理、日报和项目复盘提供可编辑模板。
- 每个自动化绑定项目/工作区、输入范围、模型、技能、执行权限和时间规则。
- 支持预览、手动运行、暂停、恢复、最后结果、下次运行和失败记录。
- 应用未运行导致的错过执行应有明确规则：跳过、合并或由用户补跑，避免一次启动重放大量任务。
- 同一自动化避免重叠执行；失败后保留已有产物、提供修复与重试。
- 统一通知中心区分个人提醒、日程提醒、AI 审批和自动化结果；已读与已处理含义不同。
- 外部发送、共享或发布内容由单独的用户授权控制，不能因创建本地日程而被隐含触发。

## 16. 架构与数据方案

| 模块 | 权威数据及边界 |
|---|---|
| 项目/任务服务 | 项目、科研任务、里程碑及对象关联；AI Run 是任务的一次执行 |
| 日历服务 | 全天日期、定时事件、时区、重复规则、例外与任务安排 |
| 阅读专注服务 | 阅读场景状态、唯一活动计时、论文分段记录、暂停区间；主进程持有 |
| 提醒服务 | 阅读提醒绑定阅读场景；与日程/AI 通知分别调度，并共用去重和通知能力 |
| 上下文/附件服务 | 用户选择范围、解析任务、版本、快照、引用与材料清理 |
| 目标/计划服务 | 目标生命周期、计划版本、执行授权和完成证据 |
| 统一 Runtime | 消息、Agent 循环、工具调用、队列、审批、取消、重放和恢复 |
| 科研成果服务 | 真实笔记、表格、报告及其来源和版本 |

- 沿用 Electron、React、SQLite 与现有服务层，通过有版本的 IPC 契约连接；UI 不持有权威执行状态。
- 所有新增数据使用新增迁移与关联表；不修改既有迁移，不通过清空库完成升级。
- 研究资料按工作区隔离；个人提醒设置按用户保存，专注记录同时具有用户归属与可选项目关联。
- 日程、提醒、AI 定时执行分别具有状态和调度规则，共用时间与通知基础设施。
- 定时和提醒引擎不依赖页面挂载；页面切换、隐藏和重载不会创建重复调度器。
- 解析、索引和耗时计算采用后台工作线程；避免主进程阻塞和并发 SQLite 写锁。
- 导出、备份、恢复和清理包含必要的计划、目标、专注、日历与附件数据。
- 内置技能、模型和用户材料都有明确版本；运行快照保留当时实际使用的内容。

## 17. 实施顺序与阶段出口

| 阶段 | 交付范围 | 进入下一阶段的条件 |
|---|---|---|
| P0 基线与设计 | 审阅未提交改动、更新需求对应表、确认数据模型及页面骨架 | 现有文献/会话无回归；区分当前能力与待实现要求 |
| P1 日常科研台 | 今日首页、项目/任务、日历完善、阅读器番茄钟、阅读提醒与免打扰 | 从安排阅读到打开论文、专注、休息与恢复可以完整使用 |
| P2 材料与技能 | 文件附件、解析预览、材料面板、来源定位、技能管理 | 附件实际入模且可引用；解析失败和重试有完整行为 |
| P3 Agent 核心 | 观察驱动循环、计划版本执行、目标状态和续跑、干预及恢复 | 多阶段真实任务按目标完成，停止/审批/重启不重复写入 |
| P4 科研闭环 | 研究日志、轻量实验记录、成果中心、自动化、周复盘 | 项目从资料到记录、成果、复盘有连续链路 |
| P5 统一验收与发布 | 视觉、窄窗、性能、迁移、真实模型、文档与远端检查 | 所有本版必选功能通过；剩余扩展单独标记，发布内容与实际一致 |

P1 与 P2 可在数据契约稳定后并行开发；P3 依赖材料与任务模型；P4 使用前述稳定能力。后续平台扩展包括外部账户日历、跨设备同步、多人项目和计算调度，不混入本版验收。

本版必选：今日首页、项目任务、日历基础多视图、阅读场景番茄钟和提醒完整状态、首批文件格式、技能选择与验证、计划版本执行、目标生命周期、科研记录与成果链路。DOCX/XLSX、OCR、ICS 和更多内置工作流列为扩展批次，分别标记状态；外部账户同步、多人协作和计算调度另立后续版本。

不得只完成一张新页面就宣称阶段完成；每阶段都要打通数据、交互、错误恢复和代表性真实使用流程。

## 18. 验收场景与交付标准

### 18.1 必须通过的端到端场景

| 场景 | 验收要求 |
|---|---|
| 安排一天科研工作 | 新建项目任务 → 放入日历 → 关联论文 → 开始专注 → 完成并记录结果 |
| 阅读专注与休息 | 在 PDF 内完成阅读/短休/长休；多论文切换归属正确，不要求返回 Work 操作 |
| 阅读提醒与免打扰 | PDF 前台阅读累计触发；离开阅读暂停；喝水/休息提示合并或稍后，未读文献时不提醒 |
| 系统恢复 | 最小化、重载、睡眠、跨日、时间变化、退出重启后状态正确；不补发通知风暴 |
| 文件与技能 | 添加实际文件和技能 → 查看解析范围 → 规划/执行 → 从回答回看真实材料 |
| 计划执行 | 生成计划 → 修改成新版本 → 明确执行该版本；历史版本和权限可核实 |
| 长期目标 | 设置交付物 → 多轮推进 → 暂停/恢复 → 根据实际产物和验证判断完成 |
| 会话生命周期 | 搜索、重命名、分支、归档、删除及草稿隔离正确；停止只影响明确的目标 |
| 数据与隔离 | 两个工作区互不可见；升级保留论文、Zotero 题录、笔记、引用和专注记录 |
| 科研成果 | 阅读与对比产生真实笔记/表格 → 打开产物 → 后续修改 → 导出与复盘 |

### 18.2 工程与 UI 验证

- 核心状态转换、去重、工作区隔离、日期/时区/睡眠恢复和操作幂等使用有意义的自动化测试。
- 实际 Electron 界面验证点击、键盘、通知行为、窄窗、深浅主题、分栏、长会话和大量日程。
- 用真实模型验证附件理解、技能执行、多轮工具依赖、计划执行和目标完成；mock 只覆盖其模拟的部分。
- 检查指定品牌资产、图谱缩放、PDF 来源定位和详情抽取，防止 Work 升级破坏原有反馈的修复。
- 计时器与提醒必须完成持续运行和恢复验证；不能只验证按钮出现。
- 每项需求记录“当前状态、实现位置、验证证据、已知限制”；本版必选项未达标时不能改成“全部闭环”。
- 验收通过后再更新 README、GitHub Pages、版本说明并推送；CI 结果、打包、安装器和正式 Release 分别核实。
