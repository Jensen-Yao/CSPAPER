# 当前实施状态（2026-10-29）

**状态：0.21.2 AI 对比表拖动浏览与视觉重构已实现并验证；0.21.1 左栏信息架构修正已发布。完整提升计划仍未全部完成。**此前逐项对照见 [PLAN_ACCEPTANCE.md](./PLAN_ACCEPTANCE.md)。

当前 Work 的 `/plan` 生成可审阅计划但不执行工具；`/goal` 保存全局研究背景并纳入后续 Work 规划。它尚不是有独立状态、暂停/恢复、自动续跑和完成验证的长期目标系统。执行器目前仍以一次生成的静态计划为主，工具结果驱动的持续规划和实时干预也尚待完善。

Work 可显式选择技能并把技能正文快照传给本轮规划、修订和总结；技能来源及正文随运行保留。当前输入区尚不支持直接附加外部文件，仍需通过文献库导入和选择已有文献。

## 本轮核心变化

- **统一运行引擎**：全屏问答、阅读侧栏、任务对话、旧 Work、自动化、划词翻译和整页翻译进入同一套持久会话、事件、工具、审批、恢复和来源体系。
- **可溯源证据**：显式论文、PDF 选区、笔记、Web 来源、集合成员和题录条目都生成持久 Source；引用回跳保留页码与文本，并在来源版本变化时警告。
- **真实平台能力**：三文献比较、保存对比表、局限追加对应笔记、重启恢复会话/来源/笔记/对比表、继续追问的固定验收链路通过。
- **模型能力档案**：多服务商 profile+model 精确绑定；思考档位跟随模型并支持自定义；AI SDK v7 system/instructions 适配和真实 Agnes 传输通过。
- **数据边界**：当前 105 篇用户库副本被识别为 91 个生成题录页与 14 个真实 PDF；14 个 PDF 全部有 chunks。真实用户库未被写入。
- **Zotero 修复**：新增按 Zotero key 精确匹配的原文修复服务，替换前保留原 PDF 与 Markdown 备份，操作 ID 幂等，支持单篇和批量入口。当前 Zotero 磁盘没有额外可修复 PDF。
- **运行可靠性**：迁移 checksum、WAL 备份、失败迁移回滚/重试、文件和 DB 强制中断、窗口销毁、单实例、托盘恢复、工具超时、PDF 抽取取消、扫描取消和跨工作区索引隔离均有回归。
- **UI/品牌**：指定品牌图成为应用、安装器、插件和页面唯一源；标题栏/Work/网页检索/初始化向导统一；题录徽标筛选、可拖拽分栏、图谱缩放和主题星系交互完成。

## 持续迭代：PDF 阅读进度防丢（2026-10-29）

- PDF 页码原本 2 秒节流落库；在节流窗口内切换或关闭标签，待写页码可能被下一篇覆盖或随组件卸载丢失。
- 现在切换 active 标签或卸载 PDF 阅读器时会先清理节流定时器并立即补发旧文档的最新页码，再进入新文档。
- 重新打开 PDF 时继续优先使用会话内最新页码，其次使用持久 `last_page`，确保恢复到关闭前位置。

## 持续迭代：Zotero 云端同步可靠性（2026-10-29）

- stored PDF 附件下载失败或校验失败时，该条目计入失败并保留增量 `since` 游标，不再伪装成题录成功，避免真实 PDF 永久漏拉。
- 增量同步会单独扫描变更附件并补拉父条目，因为新增 PDF 附件不一定提高父条目版本；已有 `source_kind=record` 的条目如果远端后来补了 stored PDF，会下载并通过 `zotero.sync_pdf` 操作日志原子替换占位 PDF / Markdown，保留替换前备份。
- 同步失败会带回逐条错误原因；启动自动增量同步失败时发送应用通知，不再静默。
- `lastSyncAt` 按 Zotero 用户与工作区隔离；设置页同步按钮在启动同步后进入忙碌状态，避免重复触发。
